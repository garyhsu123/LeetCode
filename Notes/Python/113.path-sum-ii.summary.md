# LC 113 — Path Sum II

## Process

- Started with recursive traversal, passing a path array and its running sum downward.
- Initially considered appending when the current node was `None`; corrected this to append only at a leaf whose path sum equals `targetSum`.
- Identified that one shared path array works with backtracking: append before exploring children, then pop after both calls return.
- Asked whether the path must be copied. It does not need copying during traversal, but a copy must be saved in the result so later backtracking does not mutate an already-recorded path.

## Final approach

Use DFS recursion. For each non-null node, add its value to the current path and update the running sum. At a leaf, save a copy only if the sum is the target. Recurse into children, then pop the node value to restore the path for the sibling branch.

## Complexity

- Auxiliary space: `O(H)` for the recursion stack and current path, where `H` is tree height.
- Time: `O(N + P)`, where `P` is the total number of values copied across all returned paths; worst case `O(N^2)`.
- Including the returned result, space is `O(H + P)`, worst case `O(N^2)`.

## Recognize next time

For root-to-leaf path problems, use DFS plus a mutable path stack and backtracking. Treat leaf validation separately from the null-node base case, and copy mutable paths when recording them.
