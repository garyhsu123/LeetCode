# LC 124 — Binary Tree Maximum Path Sum

## Reflect

### Approach & Reasoning

- I used post-order DFS and separated the two values at each node: a complete path through the node and a one-branch gain returned to its parent.

### Mistake / Blocker

- I first treated an all-negative tree as if it could yield `0`; because a path must contain a node, I corrected this by starting the global maximum at negative infinity.

### Went Well

- I correctly distinguished a path that combines both child branches at the current node from the one branch that can continue upward.

### Language / Syntax

- When a nested DFS updates a variable defined in its enclosing function, I need to declare it with `nonlocal`.

### Code Review

- The extra update using the returned one-branch sum is redundant: the complete path through the node already includes the larger non-negative branch.

### Final Approach & Complexity

- Post-order DFS updates a global maximum with `left_gain + node.val + right_gain`, then returns `node.val + max(left_gain, right_gain)`.
- Time `O(N)`; call-stack space `O(H)`, worst-case `O(N)` for a skewed tree.

### Key Takeaway

- When I clamp a contribution to `0`, I should separately check whether the problem allows an empty result.
